# ことり｜Threads・楽天ROOM 投稿下書きの自動作成

## 毎朝 5:15（日本時間）に自動で行うこと

1. **テーマを選ぶ** — AI が月に1回「季節・行事・生活の悩み」から考えたテーマ（誰の悩みか・場面・カテゴリー・緊急度）、
   参考投稿から生まれたテーマ、固定テーマを混ぜて、緊急度・季節・最近使ったかで1つ選ぶ
2. **商品を選ぶ** — 楽天市場・ブックス・トラベルから候補を取り、需要（レビュー件数・ランキング）・評価・
   報酬の目安（価格×料率）・勢い（レビュー数の伸び）で点数を付ける。水曜と土曜は 💎 **発掘枠**（高評価なのにまだレビューが少ない商品）
3. **分析する** — AI が候補を5つの基準（季節需要・買い替え・比較しやすさ・写真映え・悩み直結）で採点して1つ選び、
   買う人を分析（買う直前の悩み・決め手・比較ポイント・迷う理由・期待する変化）し、切り口を20個出す
4. **書く** — 60点の下書き → 弱点の洗い出し → 100点版。役立つ投稿2本（ツリー可）＋PR1本＋楽天ROOM用コメント。
   勝ちパターン（参考投稿の型）も参考にする
5. **自動チェック** — PR表記・リンク1本・NGワード・AI っぽい言い回し・文字数（引っかかったら AI に書き直させる）
6. **確認用の PR** を作る → スマホに通知。失敗したら Issue で通知

あわせて、次の2つも作ります。

7. **集客投稿**（宣伝なし・1日1本）— ニュース・Google トレンド・はてなブックマークの見出しを集め、Claude がネット検索で
   「なぜ今話題か・親の本音」を調べてから、型の違う3案を書いて採点（共感・返信・拡散・人間らしさ）し、一番良い案を使う。
   事故・事件など、つらい話題は使わない
8. **つぶやき**（短い日常の投稿・3本）— 人間味を出すための短い投稿。「📝 ネタ帳」に書いた出来事があれば、それを使う

## 使う AI（重要度ごと・config.yaml の `ai`）

| 用途 | AI |
|---|---|
| 集客投稿（ネット検索つき）・PR 投稿・役立つ投稿 | Claude Opus 5.5 |
| テーマ作り・楽天ROOM のコメント・手動投稿ストック・参考投稿の分析 | Claude Sonnet 5.5 |
| つぶやき・コメント返しの案 | Gemini（無料。使えなければ Claude Sonnet 5.5） |

Claude が使えない（キー未登録・残高切れ）ときは自動で Gemini に切り替わり、「AI切り替え」の Issue で1回だけ知らせます（Close するまで同じお知らせは来ません）。

すべての投稿で「AI が書いたと思われない」ことを最優先にしています（話し言葉・具体的な場面・小さな本音。
「いかがでしたか」「結論から言うと」などの AI っぽい言い回しは自動チェックで書き直し）。

あなたは PR を読んで Threads・楽天ROOM にコピーして投稿し、**Merge**（使った）か **Close**（使わない）を押すだけです。

## 自動投稿（Threads）

`config.yaml` の `auto_post.enabled: true` のとき、下書きは PR を通さずにそのまま保存され、1日5回 Threads に投稿されます。

| 時間帯（日本時間） | 投稿するもの |
|---|---|
| 7:40ごろ | 📣 集客投稿（なければ役立つ投稿） |
| 10:10ごろ | 💬 つぶやき |
| 12:20ごろ | 役立つ投稿（ツリーなら続けてつなげる） |
| 15:40ごろ | 💬 つぶやき |
| 17:40ごろ | PR 投稿（本文 → 自分への返信にリンク）。推し商品 → 反響のあった話題 → 今日の下書き の順に優先。PR のない日は役立つ投稿の2本目かつぶやき |

- GitHub の定期実行は数時間遅れることがあるため、日本時間 6:00〜23:40 に20分おきに起動し、
  「時刻を過ぎて、まだ出していない枠」を出します（遅れを取り戻すときも、投稿どうしは60分以上あけます。
  締め切り: 集客投稿 14:00・午前のつぶやき 12:20・役立つ投稿 15:40・午後のつぶやき 17:40）
- 朝の下書きがまだできていなければ、自動投稿の側から下書き作りを始めます
- 管理画面の「📣 今日の投稿」で、手で投稿した下書きに「✋ 手で投稿した」を押すと記録され、自動で二重に出しません
- 自動チェックでエラーが残った下書きは投稿しません
- `pr_posts_from` の日付までは PR 投稿をしません。`pr_min_interval_days` で PR 投稿の間隔を決めます
- 結果は「📣 ことり 今日の投稿」という Issue にまとまります。良くない投稿は Threads アプリで削除してください
- すぐ止めたいとき: Actions →「ことり 自動投稿」→「…」→「Disable workflow」
- Threads のトークンは60日で切れます。登録した日を `auto_post.token_updated` に書いておくと、50日たったときに Issue で知らせます（毎週月曜に確認）

## 反響 → PR 投稿（`followup`）

毎朝、直近1週間の投稿の反響（表示・いいね・返信）を Threads から取って `data/insights/` に記録します。
集客投稿のいいねが `min_likes` 以上、かつ最近の投稿の中央値の2倍以上だったら、その話題に合う商品を楽天で探して、
「この前の投稿の続き」として PR 投稿を書きます（夜の枠で優先して投稿）。

※ 反響の取得には、Meta のアプリで権限 `threads_manage_insights` が必要です。

## コメント対応

投稿のたびに、直近3日の投稿についたコメントを確認し、AI が対応を決めて返信文の案を作ります。
管理画面の「💬 コメント返し」（`kotori/stock.html#comments`）に並ぶので、本人がコピーして返します。

| 対応 | どんなコメント |
|---|---|
| 💬 返信する | 質問・体験談・共感など、会話が続くもの（返信がつくと投稿が伸びやすい） |
| ❤️ いいねだけ | 絵文字だけ・「わかる」だけなど短い反応 |
| 🙈 返さない | 宣伝・勧誘・DM 誘導・攻撃的なもの（必要なら非表示に） |

自動で返信しないのは、機械っぽく見えやすいことと、楽天のルール上、返信にリンクや宣伝を入れられないためです。
※ コメントの取得には、Meta のアプリで権限 `threads_read_replies` が必要です。

## 手動投稿ストック（BAN 対策）

毎朝、自動投稿とは**別のテーマ・別の商品**で、手動投稿用の下書きを1セット（リンクなし2本＋PR1本＋楽天ROOM用コメント）作って `manual/` にためます。

管理画面の「✋ 手動投稿ストック」（`kotori/stock.html`）に一覧で並び、ボタンでコピー、または「Threads で開く」で投稿画面を開けます。
投稿したら「使った」を押すと、その端末では一覧から外れます。自動投稿を止めて、手動だけで運用することもできます。
`config.yaml` の `manual_stock.enabled: false` で作らないようにできます。

## 楽天ROOM（手動）

楽天ROOM には公式の投稿用 API がなく、機械で投稿すると楽天 ID（アフィリエイト報酬の受け取り先）ごと止められる危険があるため、手動で投稿します。

毎朝、ROOM に載せる商品とコメントを `room.per_day`（初期値 6）件用意し、`manual/room.json` にためます。
楽天市場の商品を優先し（ボタン1つで ROOM の投稿画面が開くため）、本は1日 `room.max_books` 件まで。
`room.sales` にセールの日程を書くと、その前の週と期間中は `room.sale_per_day` 件に増やします。
対象は楽天市場・楽天ブックスの商品だけです（楽天トラベルの宿は ROOM に載せられません）。

管理画面の「🛍️ 楽天ROOM」（`kotori/stock.html#room`）で、上から順に
「① 商品を開く」→ ROOM に投稿 →「② コメントをコピー」して貼り付け →「③ 投稿した」を押します。

## Pinterest（半自動）

毎朝、`pinterest.per_day`（初期値 2）件の商品について、ピン用の縦長画像（ことりのイラストと文字だけ。商品写真は使いません）・タイトル・説明文（#PR 付き）・楽天のリンクを作ります（`pins.py`）。
画像は `kotori/pins/` に置かれ、GitHub Pages で公開されます（コミット後1〜2分で見られるようになります）。一覧は `manual/pins.json`。

管理画面の「📌 Pinterest」（`kotori/pins.html`）で「📌 Pinterest で作成」を押すと、画像とリンクが入ったピンの作成画面が開くので、ボードを選んで保存 →「投稿した」を押します。
「📥 1週間分をダウンロード」で、まだ出していないピンを1日2枚（8:00・20:30）の予約つき .csv にまとめられます。Pinterest の「設定 → コンテンツのインポート → .csv または .txt ファイルをアップロードする」で読み込むと、予約どおりに公開されます（日時は UTC で書いています）。
ボード名は `pinterest.boards` と同じ名前で Pinterest に作っておきます。Pinterest API の審査に通ったら、自動投稿に切り替える予定です（審査用のプライバシーポリシー: `kotori/privacy.html`）。

## スマホから使う

管理画面 https://keiyamada-ui.github.io/kotori/ をホーム画面に追加すると、アプリのように使えます。
GitHub の画面に移らずに、今日の投稿・反響・お知らせ・勝ちパターン・動作状況・テーマを見られます。

ネタ帳・推し商品・参考投稿の送信や、自動投稿の停止・再開、「今すぐ下書きを作る」には、
最初に1回だけ「🔑 合い鍵の設定」（`kotori/key.html`）で GitHub の fine-grained トークン
（このリポジトリだけ・Actions と Issues を Read and write）を登録します。合い鍵はその端末の中だけに保存されます。

- ✏️ **ネタ帳** — 今日あったことを一言書くと、翌朝のつぶやきになる（本人の体験として書けるのはここに書いたことだけ）
- 💬 **コメント返し** — ついたコメントと返信文の案
- 🛒 **推し商品を紹介** — 楽天のURLを貼るだけで、その商品の下書き PR が届く（使った感想を書けば体験談として使われる）
- ⭐ **参考投稿を登録** — 伸びている投稿のスクショ（3枚まで）か文章を送ると、AI が「型」を分析して勝ちパターンに追加（外したいときは Issue を Close）。スクショは Issue のコメントに分けて送り、分析のときに組み立てて AI に見せたあと、自動で消します

## Pinterest の自動投稿（審査に通ったら）

`pinterest_api.py`。Pinterest Developers でアプリを作り、審査に通ったら:
1. GitHub Secrets に `PINTEREST_APP_ID`・`PINTEREST_APP_SECRET`（と `KOTORI_STORE_KEY`）を登録
2. Pinterest のアプリ設定の Redirect URI に `https://keiyamada-ui.github.io/kotori/pinterest.html` を登録
3. 管理画面の「📌 Pinterest」→「🔗 Pinterest とつなぐ」で1回つなぐ

つながると、自動投稿の見回り（20分おき）のたびに、時刻（8:00・20:30）を過ぎた枠があれば予約待ちのピンを1枚出し、
結果（ピンの URL・失敗）を `manual/pins.json` に記録して管理画面に表示します。
審査の最初の段階（Trial）のあいだは `config.yaml` の `pinterest.api_base` をお試し用の窓口（api-sandbox）にしておき、本番の許可が出たら切り替えます。

## イラストつきの投稿（7〜10回に1回）

毎朝の下書き作りのあと、前回イラストつきで出してから決めた回数（7〜10回）がたっていれば、
今日の PR 以外の投稿（つぶやき・集客投稿・役立つ投稿）から1本を選び、ことりの画像を見本に Gemini の画像の AI で
ふんわりしたイラストを描いて付けます（`illust.py`、`kotori/illust/`）。文字・商品・人間は描かず、別の AI が確認して
不合格なら1回描き直し、それでもダメなら付けません。管理画面の「📣 今日の投稿」で確認でき、「🖼️ イラストを外す」で外せます。
費用は1枚10円前後（月15〜20枚）。画像の AI の名前は `config.yaml` の `illust.models`。

## ルール帳（考え方・コツが増えても崩れないように）

参考投稿フォームで登録した「考え方・コツ」と、自分の投稿から学んだことは、そのまま全部を文章作りに渡すと
多すぎたりぶつかったりして AI が守りきれなくなります。そこで、材料が変わったとき（または7日おき）に Opus が全部を読み、
似たものはまとめ、ぶつかるものは優先順位（アカウントの決まり ＞ 自分の投稿の結果 ＞ 考え方・コツ）で決めて、
最大7個の「ルール帳」（`data/rulebook.json`、`rulebook.py`）にします。毎日の文章作りにはルール帳だけを添えます。
ルール帳が作れないときは、前のルール帳か、考え方・コツ5個までで続けます。管理画面の「🏆 勝ちパターン」で見られます。

## 自分の投稿から学ぶ

週1回（前回から7日以上たった朝）、直近30日の自分の投稿のうち反響が大きかったものと小さかったものを AI（Opus）に比べさせ、
「このアカウントで伸びる書き方・伸びない書き方」を `data/learned.json` に保存します（`learn.py`）。
反響のわかる投稿が10件たまってから始まり、学んだことは毎朝の文章作りすべてに添えます。管理画面の「🏆 勝ちパターン」で見られます。

## 季節感（実際の気温に合わせる）

毎朝、東京の天気予報（Open-Meteo、無料）から1週間の最高・最低気温を取り、「今はどんな季節か・この時期の行事」を
すべての文章作り（テーマ・商品選び・投稿・ROOM・ピン）に添えます（`season.py`、`data/season/`）。
季節の話題を増やすためではなく、季節外れを防ぐためのもので、季節に触れるのは数回に1回くらいにするよう指示しています。
まだ暖かいのに「ダウン」「こたつ」、涼しいのに「猛暑」「プール」のような季節外れの言葉は、確認で見つけて書き直させ、
季節外れのテーマは後回しにします。予報が取れない日は平年の気温で決めます。

## 成果の記録

毎朝の下書き作りのときに、前の日の Threads アカウント全体の反響（表示・いいね・返信・リンクのクリック・フォロワー）と、
その日の投稿数・ピンの数を `data/stats/daily.json` に記録します（`stats.py`）。
楽天アフィリエイトの売上（報酬・件数・クリック）は API がないため、管理画面の「📊 成果の記録」から月ごとに入力し、
`data/stats/earnings.json` に保存します（`affiliate_record.yml`）。記録は表計算用にダウンロードできます。

## スマホ通知とアイコンの数字

ホーム画面に追加した管理画面で「🔔 通知をオンにする」を押すと、新しいコメント・自動投稿や下書き作りの失敗をスマホに通知し、
アイコンの右上に数字が付きます（iPhone は iOS 16.4 以降。`push.py`・`kotori/sw.js`・`affiliate_push.yml`）。
通知の鍵と登録した端末は `KOTORI_STORE_KEY` で暗号化して `data/push/` に保存します。

## 最初に 1 回だけやる設定

### 1. GitHub Secrets（鍵の金庫）に登録する

Settings → Secrets and variables → Actions → New repository secret

| Name | 中身 | 必須 |
|---|---|---|
| `RAKUTEN_APP_ID` | 楽天ウェブサービスの applicationId | ✅ |
| `RAKUTEN_ACCESS_KEY` | 楽天ウェブサービスの accessKey | ✅ |
| `RAKUTEN_AFFILIATE_ID` | 楽天のアフィリエイト ID | ✅ |
| `GEMINI_API_KEY` | Google AI Studio の API キー | ✅（Claude が使えないときの予備にもなる） |
| `ANTHROPIC_API_KEY` | Claude Console の API キー | Claude を使うとき |
| `KOTORI_STORE_KEY` | 自分で決めた長いランダムな文字列（40文字以上）。スマホ通知の鍵などを暗号化して保存するのに使う。一度決めたら変えない | 通知を使うとき |
| `PINTEREST_APP_ID`・`PINTEREST_APP_SECRET` | Pinterest Developers のアプリの App ID と App secret key | Pinterest の自動投稿（審査のあと） |
| `KOTORI_THREADS_TOKEN` | kotori.family の Threads アクセストークン（長期）。権限 `threads_basic`・`threads_content_publish`・`threads_manage_insights`・`threads_read_replies` | 自動投稿するとき |

### 2. GitHub Actions が PR を作れるようにする

Settings → Actions → General → 一番下の「Workflow permissions」で

- 「Read and write permissions」を選ぶ
- 「**Allow GitHub Actions to create and approve pull requests**」にチェック
- Save

### 3. 接続テスト

Actions → 「ことり 投稿下書き」→「Run workflow」→ mode で **check-api** を選んで実行。
市場・ブックス・トラベルの3つが ✅ になれば準備完了です（ランキングだけ ⚠️ でも下書きは作れます）。
続けて mode **drafts** で実行すると、下書きの PR が 1 本届きます。月の最初の実行では、今月のテーマも一緒に作られます。

## よく変える設定

すべて [config.yaml](config.yaml) にまとまっています。

- **固定テーマ・検索キーワードを増やす・変える** → `pillars`
- **候補の条件**（レビュー件数・評価・同じ商品を再紹介するまでの日数）→ `filters`
- **発掘枠の曜日・条件** → `hidden_gems`
- **点数の重み・料率の目安** → `scoring`
- **楽天 API の URL が変わった** → `rakuten.endpoints`

AI が考えたテーマは `data/themes/年-月.json` にあります。合わないテーマは行ごと消してください。
Actions の mode **themes** で、今月のテーマを作り直せます。
